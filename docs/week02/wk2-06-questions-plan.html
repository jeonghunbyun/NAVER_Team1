0. 수합 원칙

PM은 Project Manager, 즉 [01]–[05] 근거를 모아 최종 캠페인 기획안으로 정리하는 역할이다.

T1·T2·T3는 [05]에서 정한 로봇·플랫폼 개입 후보 구간이다.
- T1 (실외 이동 · Nuri): 5단계 실외·반실외 이동 — 중앙 창고·UAC에서 게이트·로딩존까지 반복 운반.
- T2 (실내 전달 · Rookie): 7단계 실내 전달 — 게이트·VAO에서 VIP 라운지·프레스센터·운영본부 등 건물 내부 다지점까지 전달.
- T3 (운영 로그 · ARC·NCP·Works): 3·6·8단계 — 요청·배차·인계·수령을 한 곳에 자동 기록.

  • [01] 출처가 없는 사실은 쓰지 않는다.
  • [02] As-Is에 없는 행위자는 타깃·페르소나로 쓰지 않는다.
  • [04]에서 확인된 불편에서 T1-T3를 도출한다. 근거가 약한 것은 가설로 표시한다.
  • 기술 설명보다 도메인, 타깃, 인사이트, 커뮤니케이션을 먼저 쓴다.
  • 기대효과는 숫자가 없으면 가설로 두고, 발표에서는 과장하지 않는다.

1. 공식 5단계와 WK2 근거 연결

WK2는 Week 2 문서 묶음이다. [00]–[06]은 이번 주차 작업 파일 번호다. 아래 표는 각 발표 단계별로 이미 확보한 근거와 다음 제작 방향을 함께 정리한다.

공식 단계 발표에서 답해야 할 질문 지금 확보한 근거 지금 상태와 다음에 할 일
1. 새 도메인·타깃 어디에, 누구에게, 왜 이 로봇을 제안하는가? 실제 키트(D1), 이동 동선(D2), 사우디 맥락(D5), As-Is 8단계([02]) 발표 가능 — 다음 단계는 한 장짜리 “새 도메인 정의” 슬라이드로 압축
2. 타깃 인사이트 그 타깃은 지금 어떤 불편과 불안을 겪는가? P1–P5 페르소나([03]), 5 이동·6 인계·7 전달 불편 집중([04]) 발표 가능 — 다음 단계는 P1–P5를 모두 말하지 말고 핵심 2갈래(정보 공백/반복 부담)로 요약
3. 빅 아이디어 한 문장으로 어떤 관점을 제안하는가? T1·T2·T3 연결 구조([05]), Human-Stay 원칙([05] §6) 카피 초안 있음 — 다음 단계는 Backstage Moves the World. NAVER Moves the Backstage.와 Nuri(빛) 네이밍을 한 장면으로 묶기
4. 광고 실행안 어떤 접점과 장면으로 “도입해볼까?”를 만들 것인가? Key Visual, Demo Dashboard, Backstage Kit Map 후보 구성 초안 있음 — 다음 단계는 1개 메인 필름 + 2개 보조 산출물로 줄여 제작 우선순위 확정
5. 기대효과 NAVER LABS와 사우디 타깃에게 무엇이 남는가? 사우디 디지털 트윈·NHC 연결([05] §7), 확장 로드맵([05] §9) 논리 초안 있음 — 다음 단계는 “행사 운영 효율”과 “도시 확장 자산” 두 문장으로 정리

2. 1단계 — 새 도메인 발견 + 타깃 정의

D1–D8은 [WK2][01]의 자료 묶음 번호다. 예를 들어 D1은 키트 사례, D5는 사우디 맥락, D8은 행사 이후 확장이다.

항목 내용 어디서 나온 근거인지 · 발표에서 쓸 말
선택 제품 Nuri(룽고, 실외) + Rookie(실내) [05] §7: 룽고는 실외 운행 안전인증과 ARC 관제를 갖췄고, Rookie는 1784에서 실내 운영 경험이 있다. 발표에서는 “실외 이동은 Nuri, 실내 전달은 Rookie”로 단순화
선택 시장 사우디아라비아 [01] D5: Expo 2030·FIFA 2034·리야드 시즌 등 메가이벤트 집중, 폭염·디야파·Vision 2030 맥락
새 도메인 국가행사 백오피스 키트 물류 (관객에게 보이지 않는 무대 뒤 운영) [01] D1·D2: 인증 배지·유니폼·프레스 키트·VIP 웰컴박스가 창고에서 인증센터(UAC·VAO)·메인 프레스센터(MPC)·VIP 라운지로 옮겨진다
핵심 타깃 행사 운영본부·의전·미디어·백오피스 물류·보안 담당 ([03] P1–P5) [02] 행위자와 [03] P1–P5가 일치. 발표에서는 “결정권자 P1 + 현장 압박 P2–P5”로 묶기
도입 의사결정자 Venue Operations Manager 등 행사 운영본부 ([03] P1) [03] P1: 직접 운반하지 않지만 지연·누락·기록 불일치의 최종 책임자
현장 운영자 백오피스 물류(P4)·미디어(P3)·보안(P5) [03] P3–P5: 취재 지연, 반복 왕복, 수기 기록 부담을 직접 겪는 사람들
이 도메인이 “아직 닿지 않은” 이유 로봇 자동화는 창고 안(AGV)·라스트마일 배송에 쏠려 있고, 행사 창고→현장→실내로 이어지는 백오피스 키트 물류는 아직 로봇이 다루지 않는 빈 구간이다 [01] D6·[05] §8: 창고 AGV는 창고 내부, 인증 SW는 사람·배지 중심. Event Chain은 물건 이동과 운영 로그를 함께 묶음
캠페인 목표 반응 “우리 행사·시설에도 도입해볼까?” 가이드라인 기준. 다음 단계는 Decider One-Pager에서 “우리 행사에도 적용 가능한 조건” 체크리스트로 보여주기

2.1 타깃 확정 조건

아래 네 조건이 모두 충족돼야 “진짜 타깃”이다. [01]–[05]로 확인된 결과를 함께 적는다.

조건 확인할 것 지금 상태와 다음에 할 일
실제 업무가 있다 요청·구성·이동·인계·수령 기록이 실제 자료에 나온다 확인됨 — [02] 8단계. 더 다듬으면: 슬라이드에서는 8단계 전체보다 5·6·7 단계만 확대
실제 책임자가 있다 운영본부·의전·미디어·물류·보안 행위자가 확인된다 확인됨 — [03] P1–P5. 더 다듬으면: P1은 Decider, P2–P5는 영향받는 현장 담당으로 나누기
도입 이유가 있다 누락·지연·기록 부재·폭염·보안 리스크가 확인된다 확인됨 — [04] 핵심 불편 5개. 더 다듬으면: “정보 공백”과 “반복 부담” 두 단어로 압축
NAVER가 설명할 수 있다 Nuri·Rookie·ARC·Maps·Works·NCP 역할이 과장 없이 연결된다 확인됨 — [05] §7. 더 다듬으면: 기술 나열보다 T1·T2·T3 도식으로 설명

3. 2단계 — 타깃 인사이트

인사이트는 “로봇이 좋다”가 아니라, 타깃이 지금 멈칫하는 이유와 바꾸고 싶은 순간을 잡는다. 모든 불편은 [04]에서 확인됐고, 1인칭 문장은 인터뷰 전 가설이다.

타깃 현재 불편 숨은 우려 보고서 문장 어디서 나온 근거인지 · 다음에 할 일
Venue Operations Manager (P1) 키트 위치·수령 현황을 실시간으로 못 본다 데모만 화려하고 현장 기록·인증 불안 “수령·인계가 실시간 기록되는 운영 구조가 필요하다” [04] 불편 #1: 6단계 인계·8단계 기록에서 현황이 안 보인다. 더 다듬으면: Demo Dashboard 첫 화면을 P1용 “전체 현황판”으로 제작
VIP Hospitality Coordinator (P2) VIP 박스 위치·구성을 도착 직전까지 확신 못 함 로봇이 VIP 응대로 오해될까 “의전은 사람, 반복 이동은 로봇” [04] 불편 #2: 5단계 이동·6단계 인계·7단계 전달에 불안이 몰린다. 더 다듬으면: Hero Film에서 VIP 앞 응대는 사람, 뒤편 이동은 로봇으로 분리
Media Center Manager (P3) 미수신·대기·IT 장애로 취재가 지연된다 기록 없으면 책임 소재 불명 “창고→프레스센터 동선에 운영 로그” [04] 불편 #3: 키트 수령 안내 메일 지연·메인 프레스센터(MPC) 대기·IT 장애. 더 다듬으면: 프레스 키트 도착 알림 장면 추가
Backstage Logistics Staff (P4) 폭염 속 반복 왕복·재분류 부담 일자리 대체 우려 “위험 구간 이동 부담만 줄인다” [04] 불편 #4: 43℃ 폭염·정오 시간대 작업 제한·키트 재분류 부담. 더 다듬으면: Before/After 장면에서 사람의 왕복 횟수를 줄이는 구조로 표현
Security / Accreditation Officer (P5) 수령·인계·재발급 기록이 흩어진다 보안 승인 자동화 오해 “보안 최종 판단은 사람” [04] 불편 #5: 손으로 적은 기록이 흩어지고, 전산이 멈추면 수기로 되돌아간다. 더 다듬으면: 보안 승인은 사람이 누르고, 로그만 자동 기록되는 UI로 표현

3.1 수업 이론 연결

같은 사실도 타깃에 따라 다른 설득 경로가 필요하다. ELM은 정교화 가능성 모델(고관여=근거 중심, 저관여=주변 단서), TRA는 합리적 행위 이론(주변의 인정·규범이 행동에 영향)이다.

대상 이론 연결할 메시지 어떻게 적용하나
의사결정자 ELM 중심 경로 처리 시간 약속(SLA)·운영 로그·보안·비용을 근거로 제시 P1은 감성 카피보다 “어디서 누락이 줄고, 어떤 로그가 남는지”를 본다. Decider Deck은 숫자·흐름·책임 구조 중심
현장 담당 Trying, Perception “일을 빼앗는 로봇”이 아니라 반복 이동 부담을 줄이는 도구 P4에게는 “대체”가 아니라 “폭염 속 왕복을 줄이는 도구”로 보여야 한다. Hero Film에서 스태프가 통제권을 가진 장면 필요
보안·운영팀 TRA, 주관적 규범 조직 승인, 규정 준수, 책임 로그 P5에게는 자동 승인보다 “사람 승인 + 자동 기록”이 중요하다. 보안 규정에 맞는 로그 UI로 표현
도입 범위 기대 불일치 정해진 백오피스·인계 구간으로 범위를 제한해 과한 기대를 막음 관람객 배달·무인 행사처럼 보이면 기대가 커진다. T1·T2·T3와 Human-Stay 범위를 슬라이드에서 먼저 못 박기

4. 3단계 — 빅 아이디어

항목 현재 문장 지금 상태와 다음에 할 일
영문 카피 Backstage Moves the World. NAVER Moves the Backstage. 유지 가능 — 무대 뒤가 세상을 움직이고, 그 무대 뒤를 NAVER가 움직인다는 교차 구조. 더 다듬으면: 첫 줄을 크게, 둘째 줄 NAVER Moves the Backstage를 작게 두는 2단 구성으로 문제 인식 후 5번째 슬라이드에서 공개
한국어 메시지 사람은 의전을 하고, 로봇은 보이지 않는 반복 이동을 맡는다. 유지 가능 — Human-Stay 원칙과 맞음. 더 다듬으면: “반복 이동” 옆에 “수령 로그”까지 붙여 플랫폼성을 보강
한 문장 컨셉 Nuri–Rookie Event Chain은 사우디 국가행사의 VIP·미디어·운영 키트 물류를 로봇과 NAVER 운영 로그로 잇는 백오피스 플랫폼이다. 발표용 핵심 문장 — 더 다듬으면: Nuri=실외, Rookie=실내, 운영 로그=증거를 괄호로 풀어 말하기
메인 카피 (deck) 무대 뒤가 세상을 움직이고, 네이버가 무대 뒤를 움직인다 — Backstage Moves the World. NAVER Moves the Backstage. 메인 카피 후보 — 더 다듬으면: 슬라이드에서는 “키트”보다 “무대 뒤 흐름”으로 더 크게 표현 가능
20어절 오프닝 관객 앞 무대와, 뒤에서 도는 키트는 다르다. 로봇은 반복 이동, 사람은 의전을 맡는다. 오프닝 후보 — 더 다듬으면: Decider 대상이면 “우리 행사에도 적용 가능한가?” 질문으로 끝내기
핵심 비주얼 행사장 뒤편 handoff — 창고→게이트에서 Nuri 운반, 라운지·프레스에서 사람이 키트 수령·판정. Key Visual + Backstage Kit Map (§5.1 컨셉 목업) 제작 방향 명확 — 더 다듬으면: T1·사람·T2·T3를 한 장의 맵 그래픽으로 합치기

4.1 빅 아이디어 검수 기준

[01]–[05]가 채워졌으므로 통과 여부를 판정한다.

기준 통과 여부 어디서 나온 근거인지 · 만들 때 반영할 점
로봇보다 현장 문제가 먼저 보이는가? 통과 [02] As-Is·[04] 불편을 먼저 설명하고, 로봇은 [05]에서 처음 등장한다. 제작 시 첫 3장은 로봇 사진보다 키트·동선·인계 문제 중심

5.1 캠페인 결과물 패키지

과제의 최종 결과물은 리서치 보고서가 아니라 캠페인 기획안이다. 아래 결과물은 발표에서 “확 와닿는 장면”을 만들기 위한 후보이며, 공식 로고·행사명 사용은 실제 제휴처럼 보이지 않게 컨셉 목업으로 표기한다.

결과물 보여줄 것 왜 필요한가 제작 메모 지금 상태와 다음에 할 일

Event Co-Brand Mockup Expo 2030, FIFA World Cup 2034 같은 행사 로고와 NAVER LABS를 나란히 둔 가상 이미지 시장과 도메인이 즉시 보인다 실제 로고 사용권·가이드 확인 전에는 발표 내부 목업으로만 사용 선택 제작 — 공식 파트너처럼 보일 위험이 있어, 로고 병치보다 “사우디 메가이벤트 맥락” 배경으로 처리

5.3 Q5 — 핵심 인프라 vs 보조 확장

Q5는 다섯 번째 검증 질문이라는 뜻이다. NAVER 인프라를 “없으면 안 되는 핵심”과 “나중에 붙일 보조 확장”으로 나눈다. 판정은 [05] §7을 따른다.

구분 판단 질문 답 어디서 나온 근거인지 · 발표에서 다룰 법
핵심 인프라 T1-T3 운영에 없으면 서비스가 성립하지 않는가? Nuri·Rookie·ARC·NCP·Maps·Works는 없으면 체인이 끊긴다 [05] §7: T1은 Nuri, T2는 Rookie, T3는 ARC·NCP·Works. 발표에서는 “로봇 2대 + 로그 1개”로 단순화
핵심 인프라 요청·배차·경로·인계·수령 기록 중 어느 단계에 직접 연결되는가? 요청·승인=Works, 배차·경로=ARC·Maps, 이동=Nuri·Rookie, 인계·수령 로그=ARC·NCP [05] §2.0·§7: 한 장의 흐름도에 연결. 더 다듬으면: Demo Dashboard에서 이 4단계를 클릭 흐름으로 보여주기
핵심 인프라 행사 보안·장소·운영 흐름과 직접 연결되는가? Maps·HD Map이 보안구역·경로를, Place가 목적지를 잡는다 [05] §7: 사우디 도시 디지털 트윈·ALIKE·ARC eye 근거. 발표에서는 “지도는 이미 네이버의 강점”으로 처리
보조 확장 없어도 백오피스 운영은 가능한가? Place·Pay·Commerce는 없어도 핵심 키트 물류는 돌아간다 [05] §7·§10: Place는 목적지 편의, Pay·Commerce는 IP 굿즈·결제 확장. 본편에서는 보조로 짧게
보조 확장 발표에서 과장으로 보일 위험이 있는가? Pay·Commerce를 핵심처럼 말하면 과장 — IP 굿즈 결제 등 보조로만 Q&A 리스크: “결제 플랫폼” 발표가 아니라 “운영 체인” 발표다. 더 다듬으면: 결제는 마지막 IP 확장 한 줄로 제한

6. 5단계 — 기대효과

숫자가 없는 항목은 가설로 둔다. 발표에서는 “줄어든다·가능해진다”로 말하고, 구체 수치는 1차 데이터 확보 후 채운다.

효과 누구에게 설명 어디서 나온 근거인지 지금 상태와 다음에 할 일
운영 효과 행사 운영본부 반복 이동·기록 공백이 줄어 현황 가시성이 오르고 지연·누락이 준다 [04] #1·#4: P1 정보 공백, P4 반복 왕복 논리 타당 — 더 다듬으면: “왕복 횟수/수령 확인 시간” 같은 수치가 있으면 정량 효과로 전환
의전·미디어 효과 VIP·프레스 담당 박스 위치·도착이 실시간으로 보여 의전 사고와 취재 지연이 준다 [04] #2·#3: VIP 박스 위치 불안, 미디어 대기·IT 장애 논리 타당 — 더 다듬으면: Hero Film에서 VIP·기자 앞 문제가 터지기 전, 뒤편에서 해결되는 장면으로 표현
보안·책임 효과 보안·accreditation 담당 수령·인계·재발급이 자동 로그로 남아 사후 입증이 쉬워진다 [04] #5·[05] T3: 기록 분산·수기 전환 논리 타당 — 더 다듬으면: 로그 UI에 “누가/언제/어디서/무엇을” 필드를 보이게 제작
NAVER 가치 NAVER LABS 로봇 판매가 아니라 행사·도시를 잇는 Physical AI 운영 레이어를 제안 [05] §7: 로봇·ARC·사우디 디지털 트윈·Works 연결 근거 강함 — 더 다듬으면: “로봇 회사”가 아니라 “공간 운영 OS”라는 표현으로 정리
지속 확장 사우디 주거·스마트시티 행사 후 주거단지 프라이버시 라스트미터로 확장 [05] §9: NHC·ROSHN·마즐리스 로드맵 확장 가설 — 더 다듬으면: 본편의 주장이 아니라 마지막 기대효과 슬라이드에서 짧게 연결

6.1 Q6 — 행사 이후 확장

Q6는 여섯 번째 검증 질문이라는 뜻이다. 행사 때 만든 로봇·지도·운영 로그가 행사 후에도 쓸 수 있는지 본다. 답은 [05] §9 확장 로드맵을 따른다.

확장 질문 답 어디서 나온 근거인지 · 발표에서 다룰 법
행사에서 만든 로봇 플릿을 어떤 주거단지 운영으로 옮길 수 있는가? NHC·ROSHN 주거단지 (네이버-NHC 합작법인 ‘네이버 이노베이션’) [05] §9-4: NHC 연결은 강한 근거. 발표에서는 “행사 후 도시 인프라로 확장” 한 줄로 처리
행사장 지도·인계 지점 개념이 주거단지에도 필요한가? 필요 — 단지 내 경로와 지정 지점 수령에 그대로 쓰인다 [01] D8: 플릿·경로·인계 지점 재사용. 더 다듬으면: 행사장 픽업존 → 단지 커뮤니티 허브로 변환 그림
사우디 주거문화에서 프라이버시 라스트미터가 왜 설득력 있는가? 디야파·프라이버시 존중 문화와 ‘지정 지점 수령’이 잘 맞는다 [05] §9-5: 마즐리스·프라이버시 맥락. 발표에서는 문화 설명을 길게 하지 말고 “집 앞 직접 대면보다 지정 지점 수령”으로 단순화
운영 주체는 NHC, ROSHN, 디벨로퍼, 시설 운영사 중 누구인가? NHC·ROSHN·디벨로퍼 (네이버 이노베이션이 사업 기반) [01] D8·[05] §9: 사업 기반 설명용. 본 발표에서는 세부 영업 구조보다 확장 가능성 근거로만 사용
